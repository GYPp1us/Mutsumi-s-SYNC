# HZ V4 试用验收（2026-10-25）

环境为 HZ 的 2 vCPU、约 1.6 GiB 内存与 4 GiB swap，Rust 1.95.0。运行、编辑与接入说明见 [HZ 试用服务](hz-trial.md)。这是单次部署验收，不是延迟分位数或完整 QQ 生产认证。

## 已验证的真实路径

- `https://hz.arcol.site/sync/health` 从本机访问成功。Rust 服务使用专用 `mutsumi-v4` 用户与回环端口，nginx 提供 HTTPS。V3 继续保持停止和归档。
- Command Code key 经用户明确授权通过 SSH 标准输入写入 HZ，环境文件 root:root 0600；没有放进仓库、命令参数或网页。HZ 对 `deepseek/deepseek-v4.1-flash` 的实际调用返回成功。
- 访问口令登录、会话 Cookie 和匿名 API 拒绝均已测试；每来源上报口令独立。身份伪造、CSRF 和重复事件规则另由离线 HTTP 测试覆盖。
- 真实 typing-cat GIF（1,776,311 字节）和 This Is Fine 漫画 PNG（874,268 字节）经实际上传、鉴权下载，返回字节与源文件完全相同。
- 漫画经过真实多模态观察。模型识别出着火房间中的狗、喝水、最终被烧伤的连续画面，并解释强装镇定的梗意；主要内容经原图核对，观察中的局部动作不确定性被保留。行动模型将文字、原图 `media_id` 和收尾文字作为同一条消息的三个有序段保存到网页。
- 主人指令触发 edit、bash、wait；测试服务仅在真实 wait 动作开始后提交子代理报告。上报及时入库、相同事件被去重，最终回复包含新报告编号。没有向 QQ 发消息。
- 最终版本重新完成整套真实模型测试：文件内容精确相等，bash exit_code=0 且 stdout 为实际文件内容，wait 成功，最终回复同时包含文件标记和等待期间到达的报告编号，所有检查通过。
- 在线模型实际调用 `render_markdown`，生成中文、列表、数学公式和 Mermaid 流程图，经媒体登记与消息发送后从网页 API 取回 640×303 PNG。中文、公式和图形经画面核对可读，使用真实 md2svg/resvg worker。

## 发现并修正的问题

第一次实际服务测试中，edit 和 wait 成功，bash 返回 exit_code=1：受系统服务保护的进程视图内无法再次挂载 procfs。模型明确报告两次 bash 读取失败，区分 edit 写入回执与独立读取证据，没有声称 cat 已成功。

沙箱改为提供空的 `/proc`，保留 PID、网络和文件系统隔离以及全部 systemd 限制。相同服务限制下的临时探针已验证可以执行命令，同时无法访问宿主业务目录和进程环境。超时仍记录部分效果并停止推进；非零退出码仍作为真实工具结果提供给模型。

构建包曾遗漏 SQL 内嵌资源，已补齐，并新增只选择 Git 跟踪文件的 `deploy/hz/source_bundle.py`，自动检查 SQL、HTML、JavaScript 等必要输入。初次渲染器构建被 SSH 断线中断，恢复后由服务器一次性构建单元执行并保存日志。
