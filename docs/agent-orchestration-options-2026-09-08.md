# 让模型自由做事，也能及时、有意图地开口

Mutsumi's SYNC · 暂定方案：自主编排、独立审查与及时表达意图 · 2026-09-08

仓库清理、历史资料归档和后续实验接手说明见[《仓库清理、设计修改与实验接手报告》](repository-cleanup-and-experiment-plan-2026-09-08.md)。

这次设计以保留模型的完整编排能力为先。模型应能自行选择说话对象、组织多方交流、调用不同设备、等待、回想上文和改变计划；这些能力可以自由组合，不需要我们先为每一种组合设计流程。

此前方案中的两项主张撤回：固定时间自动发送等待短句，以及把任务结果固定送回发起会话。前者没有解决有意义的交流，后者提前封死了模型可以选择的路径。已有原型保留为实验记录，暂停沿着这两个假设扩展。

## 当前暂定：模型自主行动，输出和工具独立审查

模型保留完整编排能力。发送时，可以在输出中填写目标等参数，也可以调用重定向工具选择目标；具体采用哪一种表达方式，留到实现时决定。两种方式都在实际发送前经过独立审查，不因更换表达方式而绕过核对。

审查同样放在 bash 调用、子代理启动等动作之前。各处核对本次实际要发生的事情：

| 即将发生的事 | 独立审查的重点 |
| --- | --- |
| 发消息、转发、@、切换发送身份 | 说话者、接收者、会话和引用来源是否认对，内容是否符合当前意图与场景。 |
| 执行 bash 或操作设备 | 是否在正确的设备和位置做符合要求的事，有没有误解对象、范围或实际影响。 |
| 启动子代理 | 分出去的工作是否符合目标，是否带上必要原话和背景，是否与正在做的事冲突或重复。 |

子代理后续的真实输出和工具操作也经过相应审查。审查不替模型制定完整流程，也不审查每一段内部思考或递归审查审查者。发现问题时给出具体依据，让行动模型修正、继续查证或改换办法；无需把每次分歧都变成人工审批。

## 及时表达意图：改写请求，交给关闭思考的模型

原任务继续交给能够深入思考、自主编排的模型。同时，把当前请求改写成一个短问题，交给关闭思考的模型：**现在根据已有信息，可以自然表达什么打算？** 它无需解完整道题，也不等待另一个模型先产出答案或工具说明。

这个短请求同时提供人设、眼前说话者、必要上文和实际进展。可以这样说明它的目标：

> 先判断此刻是否值得接话。结合用户要求、角色设定和已有事实，用自然的话表达现在有依据的意图，例如思考、查找、尝试或去询问某人；也可以自行选择更合适的表达。不要为了接话而求出完整答案，不要虚构已经发生的进展。可以直接回答简单问题，也可以保持沉默或说多条。

预设分类用于提供思考方向和场景示例，不限定角色只能说哪几句，也不决定后续必须执行哪一套流程。初版可以保留“思考、查找、尝试、询问”等参考，同时允许自由发挥；不必先加多个完整解题模型竞赛，才能尝试解决首句问题。

短句也经过输出侧的独立审查，但核对的只是这句话的对象、意图、事实和人设，不重新求解整个任务。关闭思考的短生成和有针对性的短审查，应该作为一条完整的早期回复路径来测量，而不能只看生成模型有多快。

需要衔接好的一点是：**已经说出的意图，要让继续做事的模型知道。** “我去群里问问”不能只是一个模型替另一个模型随口猜的计划。快速模型依据明确要求或已有打算表达意图，发出后由后续编排承接；若已有信息只支持“我先想想”，就不凭空许诺具体操作。新信息允许模型改变打算，再自然说明变化即可。

完整回复已经准备好，就可以直接回复；该沉默时也可以沉默。不要求每次都加一句开场白，也不恢复固定三秒的通用等待通知。这条路线已经暂定，实际改善程度仍待验证。

## 已说出的意图，怎样进入后续行动

核心约定是：**把实际说过的话作为角色的共同经历，在下一次行动前真正交给执行者；执行者可以承接，也可以有依据地修正。** 不把一句短表态变成必须照走的完整计划。

### 从收到请求到承接意图

1. **同时开始接话判断与深入处理。** 两边都看到用户原话、角色和来源身份、必要上文，以及已经发生的事。快速模型不替深入处理的模型猜测秘密进展，深入处理也不必等一句开场白才开始思考。
2. **快速模型提出台词，独立审查后尝试发送。** 例如“稍等，我去群里问问小林”。审查只看当前依据是否支持这句话、对象是否清楚、角色是否合适；不要求深入处理先批准完整计划。尚未发出的文字始终只是草稿。
3. **根据真实发送结果，形成共同事实。** 留下实际发送的原话、谁向谁说、对应哪段用户要求，以及发送是否确认成功。只发送了一部分，就只把那部分算作已说出；未发送的草稿不能变成对外承诺。确认发送成功也不等于对方已经阅读。
4. **执行者在下一次实际行动前读到新事实。** 它要知道：“角色刚才对这个人说了这句话；这是表达过的打算，相关操作是否已发生另看真实结果。”它据此选择下一步，再通过相应的独立审查。
5. **后续行动把这个打算往前推进，或明确改变它。** 已经问过就不再重复问，准备询问就自行组织询问方式；发现不必问、不能问或用户改口，则调整计划。只有变化会影响对方理解和期待时才需要解释，不要求逐步播报内部过程。

读历史、查资料、深入思考可以继续并行。真正需要衔接的是角色对外说了什么，以及接下来要发生什么，不是让所有参与者每走一步都重新协商整件任务。

### 如果执行模型已经在思考

不能假定把一句话记下来，正在进行的思考就会自动知道。它可能仍按旧信息提出“我现在去问小林”，却不知道角色已经这么说过，甚至另一个参与者已经问完。

因此，在它准备发消息、调用工具、启动子代理或操作设备时，要把期间新增的相关表态、用户补充和实际结果真正交给它。**尚未考虑这些新事实的旧提议不能直接执行。** 已有分析可以保留为参考，只补一次对当前局面的判断，不强迫从头重做问题。

独立审查同时看到这批最新事实，检查拟采取的行动是否真的承接了它们。审查者发现遗漏，就指出具体哪句话或哪个已发生动作需要重新考虑；它不替执行者偷偷改目标或重写计划。

审查后、实际开始前若又出现相关改口或进展，也要更新判断，不能拿旧的审查结果继续推进已经过时的动作。

已经开始的操作也不因为出现一句新表态就被当作没有发生。先如实保留它的结果，再让模型决定后续。已有子代理收到与自身工作有关的新表态，之后的实际动作同样检查；新启动的子代理则从一开始就带上这些背景。无需把所有角色和设备的全部对话都交给每个参与者。

### 一句“我去问问”究竟约束什么

它意味着角色已经向某个对象表达了这项打算，后续不能完全不知情地另做一套。它不代表已经问过，不是用户追加的新命令，也不替原任务增加授权。

执行者有三种自然的处理方式：继续推进、根据新信息调整、发现说得不合适后纠正。这里不要求再给用户发一条“已承接意图”的确认；能直接做就直接做。

例如，角色说“我去群里问问小林”，执行时发现小林刚刚已经回答了，可以直接转达：“他刚好回了，我把原话转给你。”如果用户改成“先别去群里，自己核对一下”，就按新要求处理。不能为了兑现自己先前那句话，反而违背用户刚刚说的话。

人物和场景也要一起承接。私聊里的“我去问问”，只是对私聊对象表达过；不能假设群里的人也听过。到了群里仍由模型组织适合那里的人设、称呼与内容，之后是否回私聊、继续追问或等待，也继续由模型决定。

### 两边先后顺序不同，怎样保持一致

| 当时的情况 | 处理原则 |
| --- | --- |
| 完整答案先准备好 | 审查后直接答，不为等开场白拖延；尚未发出的多余短句可以取消。 |
| 执行者先提出了一项可用动作 | 可以先审查并推进；快速表达依据最新动作调整，不能再发与进展冲突的旧台词。 |
| 短句先发出，执行者随后提出旧计划 | 把实际说过的话交给执行者，让它判断如何承接，再决定实际动作。 |
| 短句还在发送，另一路准备做相矛盾的事 | 思考与无关工作继续；冲突的实际动作先核清这句话是否可能已发出，避免同时对外作出相反决定。 |
| 短句发送失败或结果不明 | 分清“确认未发出”和“可能已发出”；不假装用户已收到，也不盲目重发。执行者依据原任务和已知情况继续，结果不明不意味着整件事无限等待。 |
| 用户补充或改变要求 | 先前说过的话保留为事实，下一步按最新要求重新判断；已经发生的事不能抹去，尚未开始的旧动作不继续机械执行。 |
| 快速模型选择沉默 | 不产生新的对外表态；这次没有加开场白，本身不取消原任务。用户要求的静默仍需在后续处理中遵守。 |

这些是任意并行交流都会遇到的先后关系，不是按业务类型增加工作流程。决定是否冲突、怎样承接、何时解释的仍然是模型；程序负责让参与者看到相同的真实往来，并落实审查后的行动顺序。

### 一个完整例子

用户私聊：“把这个答案发到项目群，问问小林有没有补充。”快速模型审查后先说：“稍等，我去群里问问小林。”深入处理可以同时查看答案和相关上文。

深入处理准备实际发消息时，读到角色已经向用户表达了这个打算，于是直接组织群里的消息并核对小林，不再给用户重复一遍开场白。群消息真正发出后，这项行动也成为其他参与者能看到的事实；“说过要问”和“已经发问”因此清楚地区分。

如果用户在群消息开始发送前补充“先别问，我改一下答案”，执行者按新要求等待。如果消息已经发出，则如实说明已经发出，再决定是否需要补充说明，不能声称自己已经阻止了发送。

小林之后的群内回复再触发新的理解与回忆。角色能结合先前的私聊、自己表达的打算和实际询问，决定转发、解释、追问或继续等待；无需事先写出整个来回流程。

## 我们实际要得到什么

用户给出复杂问题后，模型不必先得到完整答案，才有资格开口。它只要形成了真实的下一步打算，就可以表达：

| 当下的真实决定 | 可以说的话 |
| --- | --- |
| 开始理解问题、推演答案 | “我想想。” |
| 决定寻找资料 | “我找一下。” |
| 决定试一种办法，还不知道能否成功 | “我试试。” |
| 决定向群里的人求证 | “稍等，我去群里问问。” |
| 尚未决定下一步，或眼前无需接话 | 可以继续思考或保持沉默。 |

这些话由模型结合人设和场景选择，不是触发条件对应的固定句库。说了“去群里问问”，后续就应实际推进这个打算；遇到新信息也可以改变主意。表达意图不需要提前保证成功，但不能把准备做的事说成已经做完。

第一句是否有价值，要看它是否表达了真实意图、是否适合当时的关系，以及后续行为是否与之连贯。每次机械地说“我想想”，也可能退化成另一种自动确认。

这里的“完备性”，指不预先封死模型能够表达和组合的行动，不把系统做成只会走若干流程的机器人。它不等于声称模型能正确完成世界上的任何任务。99% 作为观察幻觉和错发的参考，不能成为禁止复杂任务、反复追问或永远不发送的理由。

## 备选一：一个模型先决定下一步，边做边交流

保留一个拥有全部能力的模型，让它理解：这一刻需要决定的是“接下来值得做什么”，不一定是“整个问题最终怎样解决”。

它可以先说“我先核对一下题里的条件”，随后检查；发现需要询问别人，再去群里问。回复、行动、等待和重新思考都是它自己的选择，过程中没有必须经过的接待、执行、汇报阶段。

这条路最接近目前用提示词已经能做到的行为，人格与决定也最连贯。它适合作为比较基线：如果把提示和场景示例做好就够用，不应仅仅为了架构看起来先进而增加参与者。

**弱点也很明确：第一次调用仍可能长时间不开口。** 要求它先考虑下一步，只是在改变任务目标，没有从外部消除它先想完整题的倾向。遇到这个问题，仅继续堆提示词可能收益很小。

## 备选二：几条思路同时开始，尽早采用可用的下一步

同一个复杂请求，同时交给几个拥有完整能力的模型考虑。它们可以从不同角度入手：直接求解、检查关键歧义、回想相关人物与历史，或者寻找现在就能推进的一步。角度是帮助思考的分工，不是禁止它们做其他事情的能力边界。

其中一个已经形成了有依据、符合角色的下一步，就可以成为当前采用的行动；不用等其他模型全部想完。它给出的台词可以直接成为角色的发言，不再经过一轮必需的润色。其余思路继续提供材料、质疑或更好的方向，后续仍可改换思路。

例如，一个模型还在完整计算，另一个发现答案取决于小林掌握的一项数据，就能先提出并推进：“稍等，我去问小林一个条件。”这句话改变了问题的进展，有实际意义。多个模型同时工作，是在用更多计算换取更早得到可用判断的机会。

采用标准不能只有“谁先回答”。空泛的接话、未经依据选择的人或群，以及与已经发生的事冲突的计划，都不应因为快就胜出。对同一件实际行动只采用一个决定，其他候选不能各自把消息发出去；这只是避免重复行动，不规定下一步必须做什么。

另一个同时工作的模型可以比较已经出现的建议，也可以提出自己的办法。它只需判断眼前这一步是否成立，不重新完整求解原问题；事实核对也与其他思考同时开展。不过，比较者仍可能想得过久，成为新的瓶颈，这正是实验必须揭露的问题。

**优势是直接针对单个模型卡住的问题，值得优先实验。** 风险是几个模型可能一起慢、一起误解，或者较快的思路不如较慢的完整。挑选和核对本身也会花时间，增加模型数量不保证按比例提速。

## 备选三：一个持续在场的角色，自己组织临时团队

目标是让角色在事情进行期间仍能参与新的交流，同时自行组织其他智能体处理正在进行的事情。角色本人仍拥有完整行动能力，不是只能接话的前台；帮手也不只是返回固定格式结果的工具。

角色可以临时决定：自己继续和用户讨论，请一个帮手查资料，另一个去核对群里的说法；也可以自己去群里追问，把深入计算交出去。有人提出新要求后，它可以调整分工、收回一个决定，或者让两种思路继续比较。分工随问题变化，由模型组织，不由我们事先列出所有流程。

角色表达自己的真实决定。例如它亲自决定去群里问，就可以先说“稍等，我去群里问问”；它把一件事交给伙伴后，也能准确表达自己已经安排了什么。它不需要等完整结果才说话，也不能替伙伴编造进展。

参与者需要共同理解原话、人物关系、当前打算和实际发生的事。同一角色在私聊和群里说的话必须前后接得上；内部有几个思考者，不应让用户感到它突然换了人格。如果任务确实涉及不同角色，也应清楚是谁在说什么，而不是把所有人的意图混成一个声音。

**优势是改善长时间任务期间的交流，适合多方、多轮、多设备的场景。** 它本身不解决主导模型首次迟迟不开口的问题。风险还包括协调本身变成负担：有人依据旧信息行动，有人作出另一个参与者无法兑现的承诺，或者最终仍要等一个主导模型拿主意。它也容易退回上一版的接话模型与工作模型分裂，需要特别观察。

## 三个方案都必须允许这个场景自然发展

用户在私聊里说：“把答案发到项目群，@小林。”

角色可以先说“我先整理答案，发到项目群后提醒小林”。如果发现答案缺少关键条件，它也可以决定先求证，再完成发送。它决定发到哪个群、怎样称呼对方、发几条，或者是否还需要向用户确认某个具体歧义。发送后，它可以继续聊天，也可以安静等着，不必反复同步状态。

稍后，小林在群里说：“第二项要改，明天的新数据才准。”这条群消息本身就能让角色想起先前的私聊要求。它可以转发原消息给用户，附一句“他提醒第二项还得改”；也可以先在群里追问、查看另一台设备上的资料，再回私聊解释。应不应该等到明天，同样由模型结合上下文判断。

用户没有另外写出“等待小林回复”的指令，角色仍然可以判断这条后续讨论值得让用户知道。是否跟进、何时转达，以及哪些消息不相关，都由它结合原意和新局面决定。

即使小林没有引用原问题，只说了一条有用的新线索，模型也应有机会意识到两者相关。记忆帮助它找回原话和实际往来，不能把“有没有事先登记等待条件”变成能否想起这件事的前提。收到消息的地方，也不限定这次必须把回复发到哪里。

多一个人、换一个群、再增加一台设备，应当只是模型面对的新局面。需要新增的是可使用的能力和可查证的事实，不是为每种排列新增一条工作流程。

## 发送目标究竟怎样选择

建议采用这个核心逻辑：**模型决定这一步想对谁做什么，再把这个意图对应到真实的人、会话和设备；另一份独立判断检查两者是否一致。** 判断的对象是当前这一步，不需要先生成整件事的完整流程。

### 一次发送要分清四件事

| 问题 | 为什么不能混在一起 |
| --- | --- |
| 谁在发言？ | 机器人当前代表哪个角色、使用哪个实际账号。内部哪个模型想出了这句话，不决定它的对外身份。 |
| 希望谁看到、谁注意到？ | 发到项目群意味着群成员可见；@小林意味着特别提醒小林，不等于改成给小林发私聊。 |
| 通过哪里送达或执行？ | 同一个人可能有不同私聊入口和设备。手机发来的要求，不代表结果必须发回手机；用于查文件的电脑，也不自动成为消息收件人。 |
| 在转述谁的什么话？ | 小林是原消息作者，机器人是转发者，用户是接收者。这三个身份不能因为一段引用而混淆。 |

这些不是限制任务类型的分类。它们只是把任何一次收发本来就存在的区别说清楚。模型可以选择一个或多个目标，继续等待、改变计划，也可以决定本次不发消息。

### 先理解当前意图，不从消息来源猜收件人

行动模型结合当前消息、相关原话、自己已经说过和做过的事，形成一个可以直说的决定。例如：“把刚收到的小林回复转给先前私聊的用户，帮助他了解答案需要调整。”

随后再确定这句话中的“小林”“用户”“私聊”各自指谁、在哪里。这里保留的是决定与依据，不要求公开或保存模型完整的思考过程。

当前群消息只说明谁刚才在哪里说了什么，不能直接推出这次也该回复那个群。原先由谁提出要求，也不代表所有后续结果都必须回到他那里；用户可能已经改口，模型也可能有依据先去找另一个人求证。

依据不必总是一句逐字对应的用户命令。模型自主决定找谁协商，同样是合法的编排；核对要判断这个决定是否符合当前目的、是否认对对象，而不能要求每一步都在用户原话中提前写明。

### 把称呼对应到真实对象，让模型选择，不让它编地址

向模型提供查到的真实人物、群聊、账号和设备信息，包括必要的身份关系：哪个小林在哪个群、哪个私聊属于谁、设备由谁使用、角色能通过哪个账号行动。昵称只是线索，不能作为认定同一人的唯一依据。

模型选择的是查到的具体对象，实际送达地址由该对象的真实资料提供。这样，“语义上选对小林”和“实际发到了小林”之间不会再多一次靠模型凭记忆填写地址的机会。设备与人的对应关系也应来自可核实的信息，不能凭一句自称或相同昵称合并身份。

初次提供的对象不够，模型可以继续查找其他人、群和设备。查找范围不能被锁在当前会话或最先出现的几个候选上。对象确实尚未接入时，可以接入新的能力；不能偷偷换成名字相近或刚好可用的另一个目标。

### 让另一个模型独立选一次，而不是只问“你同意吗”

对跨会话、多人重名或多设备的选择，让另一模型看到原始要求、相关往来、本次准备做的事和真实对象资料，先不告诉它行动模型选中了谁。请它独立判断：这一步应该让谁看到、提醒谁、使用哪个身份和入口，哪些地方仍有歧义。

它也要检查这一步本身是否成立。例如群里的话只是主题相似的闲聊，与先前问题并无实际关系，就应提出“目前不应据此转发”，不能在主模型已经误判相关性的前提下继续帮它选收件人。

这份判断可以与行动模型的准备工作并行，人物查找与历史回忆也可以同时开始。核对当前对象不需要把整道题重新解一遍，但它仍有时间成本，不能保证完全没有额外等待。

两份判断对应到同一组具体对象，且相关信息没有出现变化，就可以采用这次选择。只比较是否都说了“小林”是不够的，因为它们可能指向两个不同的人。

判断不同，就查清分歧落在哪里：原话是不是看漏了、是否遗漏一次改口、两个入口是否其实属于同一个人，或者确实存在几种都合理的选择。能查到的事实直接补齐；都合理的行动由模型择优；无法从现有信息区分且会影响任务的歧义，再针对那个问题询问用户。不能用多数票把事实分歧盖过去。

独立判断一致也不证明一定正确。两个模型可能都漏看了同一段历史，因此核对者应能自行查证，而不只阅读行动模型提供的摘要。增加智能体的价值在于增加独立发现错误的机会，不在于凑出更多赞成票。

### 发送时保持模型选定的含义

实际执行要忠实对应本次选择：哪个角色发、发到哪个会话、提醒哪个人、引用哪条消息。发现对象信息变化或设备不可用，反馈给模型重新决定，不自动把消息送到另一个方便的地方。重复行动、不存在的地址和虚假的成功结果属于执行问题，不需要靠设计业务流程来防止。

## 把这套选择逻辑放回用户的例子

用户在私聊说：“把答案发到项目群，@小林。”模型作出的决定应当是：由当前角色把答案发给项目群的成员看，同时提醒该群中的小林。独立核对重点检查“项目群”和“小林”是否认对，以及有没有把群发误解成私聊。核对不需要重做答案本身。

后来小林在群里回复。回忆相关上文时，可以同时沿着人物关系、问题内容和近期未完成的打算寻找线索，再查看原始往来。即使这条消息没有引用上一条、也没有登记过等待条件，模型仍有机会找回之前的私聊要求。找回的记录供它理解关系，不直接规定应该转发到哪里。

模型决定把回复转给用户后，本次选择就变成：机器人仍是发送者，小林是被转述的作者，先前用户是接收者，目标是所选的私聊入口。独立核对再从原话和群消息推导一遍，防止把这段话回发给小林，或再次发到群里。它不把“提起了小林”当成“收件人就是小林”。

如果用户已在另一个设备补充“直接告诉设计组就行”，这条新要求会改变模型的选择；如果只是使用另一台电脑核对文件，那台电脑只是这次工作的参与者，不会因此收到本应给用户的私聊。模型可以继续追问、转发、等待或改换设备，不必建立新的收发流程。

所有实际输出仍经过独立审查，但普通接话只需针对当下表达做简短核对，不必每句都重复两份完整的目标推导。“我想想”也不应等待全体一致同意。更多查证投入跨对象选择、含糊称呼、身份切换和新旧要求冲突；这些地方正是模型容易认错、也值得花更多计算查清的部分。

## 暂定方案怎样验证

当前先验证“关闭思考的意图表达 + 自主编排 + 输出与工具独立审查”。此前三个方向保留为对照和后续扩展选择，不再把并行生成多份完整判断作为解决首句问题的前提。

| 比较 | 方案一 | 方案二 | 方案三 |
| --- | --- | --- | --- |
| 核心变化 | 同一个模型先推进下一步 | 多条思路同时争取可用判断 | 角色自主组织并行团队 |
| 最值得期待 | 轻巧、决定连贯 | 更早形成有价值的第一步 | 复杂工作与持续交流兼顾 |
| 最大疑点 | 单次长思考仍会阻塞 | 选择成本、重复思考、共同误判 | 协调成本、人格和承诺分裂 |
| 适合先回答的问题 | 现有模型加提示究竟能做到多少？ | 更多计算能否真的换来时间？ | 多方长期互动能否持续自然推进？ |

保留现有提示词作为比较基线。只有在暂定方案仍暴露出具体问题时，再决定是否需要增加并行候选或更复杂的团队协作。

比较时看四件事：第一句是否更早且表达真实意图；复杂任务是否完成、是否能适应没预设过的变化；人设和多轮承诺是否连贯；是否认错人、发错地方或虚构已经发生的事。沉默、拒绝和反复询问带来的少犯错，不能抵消任务能力下降。

特别要用同一组困难场景比较，而不只挑正常路径：重名、隔很久才回复、没有直接引用的回答、临时换目标、几个人交叉讨论、设备暂时不可用，以及用户中途改主意。多模型的意见一致，也不能当作事实正确的证明。

目前没有证据说明暂定方案已经优于现有提示词，也没有证据说明它已达到某个准确率。下一步围绕这几个判断做实验；上一版原型的固定通知和固定收发路径不再继续扩建。
