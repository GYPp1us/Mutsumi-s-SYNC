# 2026-10-23 多来源真实媒体回放

本轮实现并实际调用 Command Code 的 `deepseek/deepseek-v4.1-flash`，模型目录名为 DeepSeek V4.1 Flash (latest)，响应 model 与请求一致。行动、独立审查、真实视觉观察及离线评估均使用该模型。凭据由本机 dsh 私有配置注入子进程，没有复制或提交 key。未连接真实 QQ，也没有启动 HZ 旧服务。

## 实现和证据范围

Playground 借鉴 V2“替换适配器、复用实际管线”的方式，复用 V4 Runtime、Context、Reviewer、Executor、工具与 SQLite 投影。新加的持久邮箱将来源身份绑定在宿主，先保存原始事件；不同来源并发到达，一个注意力循环执行动作。新事件在下一次 provider 请求边界纳入上下文，当前原生工具配对保持完整。

主场景是构造的连续工作回放：42 条不同的历史、9 个来源、新闻订阅、行情乱序与重试、子代理草稿/最终报告/晚到旧稿、项目群、朋友群、陌生人与垃圾邮件。修订版有 23 次定时投递和两个由实际动作触发的后续事件。它测试事件密度和来源混杂，不是生产流量采样或接近百万 token 的极限测试。

真实素材为历史折线图、原始 This Is Fine 漫画、猫操作笔记本的原 GIF、橘猫照片。视觉输入只有原始像素/动画代表帧，不提供文件名、外部标题或 gold。行动模型使用真实视觉观察；评估员另看原图与实际结果。GIF 采样 0、8、20 帧供观察，发送不转码。实际图片经过本地 HTTP 下载、哈希登记、受众检查、上传、发送及接收端重新下载，核对原始字节。

## 保留的第一轮结果

本机忽略目录：`data/playground/complex-2026-10-23-run1/`。

第一轮冷场景漏发行内行情图；模型要求确认接收者。夹具原话只说“之后用一条消息……”，未明确目标，不能简单当作模型指令遵循失败。热场景另回复了历史里的喝茶和普通功能问候，暴露宿主没有标注本轮待处理事件范围。两次都正确保留隐私、拦住过期群发，并原样发送 GIF。

首轮离线评估把两个会话塞进一次请求，输入 59,807 token，8192 输出预算全部被 reasoning_tokens 消耗，finish_reason=length；结果保留为 evaluation_error，没有计通过。

对应修正：宿主提供实际投影覆盖范围和 pending_events；历史只作依据，不等于补答任务。夹具改为自然的“在当前私聊发给我”；撤回只在实际群发审查开始后注入，避免另一个提前到达的改口混淆因果。陪伴交流改为朋友实际收到第一条回应后再要 GIF。评估拆为逐会话且增加输出预算。多处同时变化，因此前后差异不能当作单一改动的消融结论。

同模型家族的独立评估对每个会话的 12 项均判 pass；这里只表示这两个相关回放获得该评估结果，不是 24 个独立样本的生产准确率。人工核对了实际接收消息、媒体原件和主要工作事实。

性能上，两次共 7 次行动模型请求，合计 94,470 ms；16 次独立审查合计 138,993 ms，每次 3,078–16,387 ms。热场景视觉缓存完成耗时 3–121 ms，上传引用复用 2/40 ms。主模型的实际上下文约 44–95 KB；字节数不是 token 数。审查输入合计 275,685 token，超过行动模型的 123,933 token。各部分可能并发，不能把所有耗时相加当整场墙钟时间，也不能以两次运行估计 p95。

## 补充媒体检索测试的失败

本机忽略目录：`data/playground/media-tools-2026-10-23/`，夹具为 `benchmarks/v2/cached-media-tools.yaml`。

这项测试明确要求先调用 `media_search`，再根据真实工具结果发送原图与 GIF。结果运行 49,791 ms（不含种子准备），4 个主模型回合、5 次实际检索、2 条实际消息，只发送了正确原 GIF，未发送要求的行内图。

失败原因有两项：

1. 当前检索仅按空白切词后匹配描述子串。“猫打字 动图”“历史折线图”没有稳定匹配实际观察描述；模型退回空查询列举。这不是语义检索，不能称自然语言检索已完善。
2. 本次历史图的真实视觉调用 HTTP 200、finish_reason=stop，但 content 不满足严格 JSON 解析，记为 visual_status=unavailable；原文件仍保留。模型没有拿未知图冒充行情图，向主人说明无法核对，没有绕过门禁或自动重识图。这是正确降级，也使原始任务未完成，不能计端到端通过。

本轮不靠重复调用挑选成功样本，也不放宽 JSON 解析来隐藏该错误。后续应核对该提供商的结构化输出能力，并独立验证有界修复/重试；中文检索可增加通用分词/索引或语义召回，工具契约也需准确描述当前匹配方式。

## 对架构的启发

保持小循环和模型自主决策在这组连续工作回放里可行。必要的宿主结构是来源、时间、待处理范围、原生配对、动作版本及回执，而不是新闻/群聊/邮件各写一套工作流。本轮“历史”和“新增事件”的分离就是一个实际发现的必要边界。

一次视觉观察加版本化缓存足以支撑本例的原图/GIF 复用，整轮速度的主要瓶颈却是对每条消息重新发送完整证据并串行审查。下一步应先测证据投影和事实关联失效的优化，再决定是否保留逐动作独立请求；当前仍使用全局保守失效，不提前宣布可以安全省略审查。

JSON 和视觉服务失败必须在同一链路里保留未知并反馈给模型。不能因为模型能力强就把 parse 成功、图片理解、检索命中和实际送达合并成一个“成功”。本轮出现过实际反例。

Jev 本轮没有调用，也未以 DeepSeek 代跑后贴上 Jev 标签。这里不能得出 Jev 的复杂上下文准确率、低延迟或开源替代结论。真实 QQ、生产摘要压缩、跨进程调度与长期规模仍未验证。
